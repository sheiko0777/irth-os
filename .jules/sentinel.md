## 2024-05-23 - [Timing Attacks on Webhooks]
**Vulnerability:** Length-based timing leaks in signature verification. `crypto.timingSafeEqual` throws an error if buffers have different lengths, which allows attackers to brute-force the length. Even if we check the length first (e.g. `sigBuf.length !== expBuf.length`), an early return creates a timing difference that leaks information about the expected length. Comparing strings with `===` instead of constant-time comparison is also vulnerable to timing attacks.
**Learning:** Constant-time comparisons are necessary for signature verification. However, buffers must be the exact same length. To securely compare two strings or buffers of potentially variable lengths without leaking their lengths, they must both be hashed to a constant length first (e.g., using `crypto.createHash('sha256')`).
**Prevention:** Always hash the expected and actual signatures to a constant length before comparing them using `crypto.timingSafeEqual`.
