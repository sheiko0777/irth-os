## 2024-06-12 - Fix Timing Attack Vulnerability in Webhook Verifications
**Vulnerability:** Timing attack vulnerabilities in webhook authentication routes. `aramex-webhook.ts` used standard string inequality (`!==`) to compare a secret header token against an expected environment variable. `bosta-webhook.ts` used `crypto.timingSafeEqual` but short-circuited the comparison with an early length check (`sigBuf.length !== expBuf.length`).
**Learning:** Standard string comparisons and early length checks leak the length of or the position of mismatched characters in secrets and hashes via execution time differences, allowing attackers to incrementally brute-force expected authentication values.
**Prevention:** Never use standard equality operators (`===` or `!==`) or early length check short circuits when comparing secrets or authentication tokens. Always hash both values to a constant length (e.g., using `crypto.createHash('sha256')`) to ensure equal length before comparing them directly using a constant-time comparison function like `crypto.timingSafeEqual()`.
