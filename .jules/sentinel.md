## 2025-02-23 - Prevent Length-Based Timing Vulnerabilities in Cryptographic Comparisons
**Vulnerability:** A timing attack vulnerability was identified in `bosta-webhook.ts` and `aramex-webhook.ts`. The Aramex webhook used a simple string comparison (`headerToken !== token`) which returns early on mismatch, and the Bosta webhook used an early length check (`sigBuf.length !== expBuf.length`) before calling `crypto.timingSafeEqual()`. Both approaches leak the expected length of secrets/signatures and allow attackers to brute-force or guess lengths and contents through timing variance.
**Learning:** `crypto.timingSafeEqual()` throws an error if buffers have different lengths, so developers often incorrectly short-circuit the length check (e.g., `a.length !== b.length`). Doing so undermines the protection against timing attacks. Furthermore, simple equality operators (`===` or `!==`) should never be used for sensitive tokens, API keys, or HMAC signatures.
**Prevention:** Always hash both the user-provided token/signature and the expected token/signature to a constant length (e.g., using `crypto.createHash('sha256')`) *before* comparison. Then, compare the resulting fixed-length hashes using `crypto.timingSafeEqual()`. This ensures the comparison time is identical regardless of input length or content.
