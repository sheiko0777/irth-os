## 2026-05-26 - Timing Attack Vulnerability in Webhook Token Verification
**Vulnerability:** The Aramex webhook token was being compared using a standard string equality operator (`!==`), which is susceptible to timing attacks. An attacker could potentially guess the token character by character by measuring the response time.
**Learning:** Standard string comparison operators fail fast (return false as soon as a mismatch is found). This timing difference allows attackers to iteratively guess secrets. The issue existed because the token was a simple static API token rather than an HMAC, and standard equality is the default way developers compare strings.
**Prevention:** Always use constant-time comparison functions (like `crypto.timingSafeEqual`) when comparing secrets, tokens, passwords, or HMAC signatures. Furthermore, to prevent length-based timing leaks when the expected secret length is unknown to the attacker, hash both sides to a constant length before comparing them.
