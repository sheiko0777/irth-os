## 2025-02-28 - Webhook Timing Attack Vulnerability
**Vulnerability:** A timing attack vulnerability was identified in `apps/api/src/routes/webhooks/aramex-webhook.ts`. The original code used a standard string comparison (`!==`) for the webhook token. String comparisons return early upon finding a mismatch, which leaks timing information and allows an attacker to guess the token character-by-character.
**Learning:** String equality operators (`===`, `!==`) are inherently vulnerable to timing attacks when verifying secure tokens or signatures. Cloudflare Workers supports node:crypto `timingSafeEqual`, however, `timingSafeEqual` will throw an error if the two buffers are of different lengths (thus leaking length information, which could still be abused or cause DOS).
**Prevention:** Always use `node:crypto`'s `timingSafeEqual` for comparing secrets, tokens, or hashes. To prevent length leaks, always hash BOTH the incoming token and the expected token to a constant length (e.g., using `crypto.createHash('sha256')`) BEFORE comparing them with `timingSafeEqual`.
