Specific remaining inconsistencies:

- **Token bypasses:** inline semantic `var()` references still follow theme values and are not intrinsically broken. The problematic combinations are legacy foreground aliases with hard-coded RGBA backgrounds, hex hero foregrounds, and raw palette surfaces. Examples include inventory status tints, stocktaking `bg-zinc-900` camera feedback, and enrollment’s `bg-blue-50`/`text-red-600`. [inventory:16][inventory] · [stock:640][stock-camera] · [enrollment:109][enrollment]
- **Dark-mode seams:** dialog scrim uses `--text-primary/70`, producing a pale scrim in dark mode; enrollment panels remain light; Sonner follows OS theme rather than the explicit saved override. [dialog:28][dialog] · [locale layout:108][toaster]
- **Typography/spacing:** IBM Plex landed, but KPIs retain 10px labels/11px chips; detail/finance titles use 30px while lists use 24px. Nested page `p-6`, shell padding, 20px cards and 12px radii undermine the specified scale. [KpiCard:57][kpi] · [stocktaking/page:25][stock-page] · [carbon.scss:272][shell-spacing]
- **RTL:** layout direction is correct. Back arrows are fixed-direction; stocktaking retains `ml-1`. BarChart’s SVG advances left-to-right while its HTML flex labels inherit RTL, risking reversed label/bar correspondence. [detail:50][detail] · [stock:335][stock-actions] · [BarChart:30][chart]
- **Digits/localization:** home fixes do not cover inventory quantities, detail quantities or finance counts. The shared formatter still defaults to `ar-EG`; Money forces Western digits but has no locale input and retains Arabic currency symbols. [inventory:116][inventory] · [format.ts:61][formatter] · [Money:23][money]
- **Accessibility:** shared buttons/inputs now provide 44px minimum heights. Search remains 36px with a tiny clear target; NotificationBell is approximately 36px. Invite inputs remove outlines without replacement; CommandPalette declares a modal without a focus trap or focus restoration. [button:8][button] · [search:68][search] · [NotificationBell:21][bell] · [CommandPalette:128][palette]

FormDialog also infers “submitting” from **any disabled submit button**, so invalid/pristine forms can become undismissable. Replace that heuristic with explicit pending/dirty props. [FormDialog:20][formdialog]
